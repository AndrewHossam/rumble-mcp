## 2025-03-03 - Prevent Stack Trace Leakage in Error Responses
**Vulnerability:** Global error handlers (such as top-level `catch` blocks) might assign `error.stack` to messages logged or returned by the MCP server, exposing internal file paths and execution context to clients.
**Learning:** Returning `error.stack` or `error.message` with fallback logic using nullish coalescing (e.g., `error.stack ?? error.message`) can inadvertently leak full stack traces when errors are propagated upwards or handled indiscriminately. The original `index.ts` handler contained this pattern in the top-level MCP server process exit sequence.
**Prevention:** Always serialize errors to safe strings (e.g., just `error.message` or a generic `"Internal Error"`) before passing them down through the server execution path, logging, or sending responses. Ensure all top-level catch blocks enforce this restriction.
